# ChatNow — Production Deployment Guide

This guide covers two production deployment paths:

1. **Free-Tier Cloud Hosting** (great for portfolio demos and interviews — zero upfront cost).
2. **Self-Hosted Docker + Nginx TLS (HTTPS/WSS)** on a Linux VPS (supports multi-instance `api-1` + `api-2` and optional ELK).

---

## 1. Free-Tier Cloud Stack & Honest Service Limits

| Component | Recommended Provider | Tier & Known Limits | Paid Upgrade Needed For |
|---|---|---|---|
| **Frontend (React SPA)** | **Vercel**, **Netlify**, or **Cloudflare Pages** | Free hobby tier; automatic HTTPS CDN; generous bandwidth. | Team seats / commercial SLA |
| **Backend (Node + Socket.IO)** | **Render** Web Service (`render.yaml`) | **Free tier sleeps after ~15 min of inactivity** (~50–60 s cold start on next request); single instance; **ephemeral local disk** (uploaded files clear on redeploy/restart). | Always-on uptime, multi-instance horizontal scaling, persistent disk (~$7+/mo per instance) |
| **PostgreSQL 17** | **Neon** (or Supabase) | Free tier includes ~0.5 GB storage, compute-hour monthly cap, scales to zero when idle. Supports `citext` and `pg_trgm` extensions. | High storage / sustained always-on compute |
| **Redis 7** | **Upstash** | Free tier includes daily command cap (~10,000 cmds/day) and TLS (`rediss://`). Note: Socket.IO Pub/Sub + presence heartbeats count toward commands. | Heavy real-time traffic / unlimited Pub/Sub |
| **File Storage (Uploads)** | Local disk (demo) or **Cloudflare R2 / AWS S3** | Cloudflare R2 offers 10 GB free storage/month with zero egress fees (card required for verification). | Production-durable uploads across redeploys |
| **ELK Stack (Elasticsearch + Logstash + Kibana)** | **Local Docker** (included in `docker-compose.yml`) | **No permanent free cloud tier**: Elasticsearch requires ≥ 1–2 GB RAM. Elastic Cloud offers a **14-day free trial**, then requires a paid plan. | Hosted production ELK; on Render free tier, use Render's built-in structured JSON log viewer |

## 2. Step-by-Step Free-Tier Cloud Deployment

### Step 1 — Managed PostgreSQL (Neon)
1. Create a free Neon project (PostgreSQL 17).
2. Copy the **pooled or direct connection string** (`postgresql://user:pass@host/neondb?sslmode=require`).
3. Confirm your Neon role can create extensions (`citext`, `pg_trgm` — enabled by default on Neon).

### Step 2 — Managed Redis (Upstash)
1. Create a free Upstash Redis database in the same region as your Render service.
2. Copy the **TLS Redis URL** (`rediss://default:<password>@<host>:6379`). `ioredis` automatically negotiates TLS when the scheme is `rediss://`.

### Step 3 — Deploy Backend to Render
1. Push your repository to GitHub (verify `.env` and `backend/.env` are **not** tracked by git).
2. In Render Dashboard → **New → Blueprint**, connect your GitHub repo. Render reads [render.yaml](../render.yaml) automatically.
3. Fill in the `sync: false` environment variables in Render:
   - `DATABASE_URL` = your Neon connection string
   - `REDIS_URL` = your Upstash `rediss://...` string
   - `CORS_ORIGINS` = `https://your-frontend.vercel.app` (no trailing slash)
   - `JWT_ACCESS_SECRET` = auto-generated by Render (≥ 32 chars)
4. Render runs `npm ci && npx prisma generate && npm run build`, starts with `npm run start:prod` (`npx prisma migrate deploy && node dist/server.js`), and checks `GET /api/health`.
5. Verify your deployed API:
   ```powershell
   Invoke-RestMethod https://your-chatnow-api.onrender.com/api/health
   ```
   Confirm `status: "ok"`, `checks.database: "up"`, and `checks.redis: "up"`.

### Step 4 — Deploy Frontend to Vercel (or Netlify / Cloudflare Pages)
1. Import the repository in Vercel and set **Root Directory** to `frontend`.
2. Framework preset: **Vite** (`npm run build`, output `dist`).
3. Add environment variables in Vercel Project Settings:
   - `VITE_API_BASE_URL` = `https://your-chatnow-api.onrender.com/api`
   - `VITE_SOCKET_ORIGIN` = `https://your-chatnow-api.onrender.com`
4. Deploy! Vercel applies [frontend/vercel.json](../frontend/vercel.json) (SPA fallback + security headers).
   - *Cookie note*: Cross-origin deployments (`vercel.app` → `onrender.com`) require `COOKIE_SECURE=true` and `COOKIE_SAME_SITE=none` on Render (already configured in `render.yaml`). If you instead configure a custom domain with a single-origin reverse proxy, keep `COOKIE_SAME_SITE=strict`.

## 3. Self-Hosted Multi-Instance Docker + HTTPS/WSS (Linux VPS)

For a full multi-instance deployment (`api-1` + `api-2` behind Nginx + PostgreSQL + Redis + optional ELK) on a single VPS (e.g., 4 GB+ RAM if running ELK, 2 GB RAM without ELK):

1. Clone the repo and create `.env` and `backend/.env` from `.env.example` and `backend/.env.example`.
2. Obtain TLS certificates (e.g., Let's Encrypt via Certbot) and place `fullchain.pem` and `privkey.pem` at `/etc/letsencrypt/live/<your-domain>/`.
3. Mount `infrastructure/nginx/nginx.tls.conf` into the `nginx` service and mount the certs at `/etc/nginx/certs:ro`, publishing ports `80:80` and `443:443`.
4. Set in `docker-compose.yml` / `backend/.env`:
   - `COOKIE_SECURE=true`
   - `COOKIE_SAME_SITE=strict`
   - `CORS_ORIGINS=https://<your-domain>`
5. Launch:
   ```bash
   docker compose --profile full up -d --build
   # Or with ELK stack:
   docker compose --profile full --profile elk up -d --build
   ```

## 4. Production Smoke-Test Checklist

After deploying, verify every item before sharing the link:

- [ ] `GET /api/health` returns `200` with `database: "up"` and `redis: "up"`.
- [ ] Frontend loads over `https://` and WebSocket connects over `wss://` (check DevTools → Network → WS).
- [ ] Register two users in two different browsers (or normal + Incognito).
- [ ] Reload both tabs — both remain signed in via `HttpOnly` refresh cookie with zero tokens in `localStorage`.
- [ ] Send direct messages — instant delivery, ticks progress `✓ → ✓✓ → blue ✓✓`, messages persist on reload.
- [ ] Create a group, test typing indicator, reply, edit, delete, reactions, search, and file upload.
- [ ] Confirm a third user receives `404` when requesting a private conversation URL/API directly.
